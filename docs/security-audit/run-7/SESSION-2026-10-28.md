## 3. 진행 순서

1. **환경 준비.** 이 호스트(Kiro Web)는 명령마다 새 샌드박스가 뜨고 `/projects/sandbox`만 남으며, `/run`과 cgroup이 읽기 전용이다.
   - 사설 마운트 네임스페이스에 tmpfs `/run`을 깔고 cgroup을 다시 마운트한 뒤 dockerd를 띄우는 방식(`.scratch/dk.sh`)으로 실제 Docker를 썼다.
   - 이미지 `agentbox-audit-sbx:1`(직접 빌드), `agentbox-desktop:0.1`, `buildpack-deps:noble-curl`, `ubuntu:24.04`를 준비했다.
   - 스킬은 git 게이트웨이가 막아 GitHub tarball(`c1c8a8c`)로 받았다.
   - 에이전트용 `tools/sbx.py`를 이 호스트에 맞게 다시 썼다. 메모리는 RLIMIT_DATA로, CPU는 cpuset으로 건다(이 호스트 cgroup에는 memory·CPU 쿼터가 없다).
2. **정찰(부모, 0회).** `architecture.md` 0절에 변경분과 신뢰 경계 그림을 썼다. parent-live로 정찰 단서 3개를 확인했다(링크 끝 조각 쓰기, 틸드 미동작, 링크 루프는 실패하지 않음).
3. **장부와 헌터.** 7단위 장부(`seed7.py`)를 만들고 헌터 6명을 병렬로 돌렸다. 후보 4건이 나왔고 3단위는 covered로 닫혔다.
4. **3단계 검증 4회, 5단계 레코드 검증 3회.** 확정 2, 검증 필요 2. 승인 카드 렌더링 비용과 compose의 `disk_low`는 parent-live로도 쟀다.
5. **critic-1(`stop: false`).** IF-policy 단위의 `resolve()` 실패 경로가 확인되지 않았다고 지적했다. parent-live로 pid 채우기 공격을 재현했다. 첫 시도는 백그라운드 `tail`이 exec를 60초씩 붙잡아 멈췄고, 제한 시간을 줄여 다시 돌렸다. 예산 상한을 20으로 올린 뒤 2차 헌터·3단계·5단계로 F3를 확정했다.
6. **critic-2(`stop: true`), 보고서 작성.** 한국어 보고서 3종과 HANDOFF 절을 쓰고, 초안 PR #27을 올렸다.
7. **병합.** CI 통과 뒤 병합하려 했으나 이 환경의 REST API로는 초안을 해제할 수 없어 #27을 닫고 같은 커밋으로 #28을 열어 병합했다.

## 4. 표준 절차에서 벗어난 것

모두 `run-metadata.json`의 `deviations`에 적었다.
- **모델:** 서브에이전트 도구에 모델 선택 인수가 없어, 소유자가 요청한 Sonnet 5.5로 바꾸지 못하고 모두 세션 모델(Claude Opus 5.5)로 돌았다.
- **단발 리뷰 보고서:** 본문이 첨부되지 않아, 소유자 요약에 나온 F2 컨테이너 단계만 항목으로 넣고 나머지 검증 필요 건은 IF 단위의 불변식으로 덮었다.
- **결과 옮겨 적기:** 헌터·검증자 출력은 부모가 파일로 옮겨 적었다. 그 과정에서 지문 3개를 `경로:심볼:설명` 형식으로 바꿨다. 잘린 3단계 출력 1건은 부모가 복원했고 5단계에서 다시 확인했다.
- **5단계 묶음:** 예산 때문에 검증 필요 2건은 한 번의 호출로 차례로 확인했다.
- **비실질 교체:** 5단계의 F1 교체(문구·수정안·근거 보강)는 판정과 근본 원인이 그대로여서 새 검증자 없이 적용했다.
- **parent-live 설정:** 이 호스트는 CPU 쿼터를 걸 수 없어 `AGENTBOX_CPUS=0`으로 돌렸다.
